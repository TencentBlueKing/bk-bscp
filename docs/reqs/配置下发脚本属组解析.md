## 需求背景

BSCP 下发配置时，属主（owner）与属组（group）由用户在配置项权限表单中填写，随任务载荷下发到目标机，
由 `ScriptBuilder` 生成的脚本在目标机上完成归属设置。目标机侧对属组的解析存在两类不可靠依赖：

| 平台 | 旧实现 | 不可靠点 |
|------|--------|----------|
| Linux | `getent group` 预检 + `chown owner:group` | 容器/精简镜像无 `getent` 或组库不全；用户填写的属组在目标机上常常不存在，预检直接失败 |
| Windows | 经 WMI 查询账号所属组 + `icacls` 授权 | 域账号、服务账号通过 WMI 查不到关联组；查询本身受 WMI 服务状态影响 |

两类失败都发生在写盘前的预检阶段，表现为整个下发任务失败（此前属组解析不出来就 `GROUP_NOT_FOUND` 退出），
而业务真正关心的只是「文件归某用户所有」。

用户故事：

- 作为配置管理员，我希望只填写属主即可完成下发，不必为每台目标机维护一个真实存在的属组名；
- 作为业务方运维，我希望下发不因目标机组解析差异而失败。

## 改动范围（已实现）

| 模块 | 改动 |
|------|------|
| `buildLinuxPushScript` | 移除 `GROUP` 参数与 `getent` 预检；改为 `id -u` / `id -g` 取属主 UID 与主组 GID；新建目录、备份文件、临时文件、目标文件统一按 `OWNER:GROUP_GID` 归属 |
| `buildWindowsPushScript` | 移除属组预检与 `GROUP_NOT_FOUND`；新增 `windowsAdminGroup = "Administrators"` 常量，属组固定为内置管理员组；属主统一走 `BSCP_OWNER` 变量，`NTAccount` 预检改用 `$env:BSCP_OWNER` |
| 入参校验 | Windows 下发脚本新增目标路径校验（新增 `windowsAbsPathRe`），相对路径与驱动器相对路径（`C:app.conf`）直接报错 |
| 单元测试 | 同步断言，新增 Windows 侧绝对路径校验用例 |
| 函数签名 | `buildLinuxPushScript` / `buildWindowsPushScript` 去掉 `group` 形参；`BuildConfigPushScript` 为兼容调用方保留 `group` 入参但已忽略 |

## 测试重点

1. **Linux**：`id -u`/`id -g` 解析成功与失败路径；属主不存在时必须在 `mkdir` 前输出 `OWNER_NOT_FOUND` 退出；
   新建目录按 `OWNER:GROUP_GID` 归属且只作用于本次新建层级；备份文件、临时文件、目标文件属组一致；
   备份轮转与 SELinux `chcon` 继承无回归。
2. **Windows**：属主预检走 `set "BSCP_OWNER=..."` + `$env:BSCP_OWNER`；`TARGET_GROUP=Administrators` 对目录 `(RX)`、对文件 `(R)`；
   属主 `(F)` 与 `/setowner` 生效；任一步 icacls 失败即终止并拆掉本次新建的空目录。
3. **新增校验**：`relative\path.conf`、`C:app.conf` 返回 `absPath must be absolute`；`D:\app\conf\app.conf` 与 UNC 路径正常通过。
4. **回归**：下发后目标目录无 `.b64` / `.out` 临时残留；同主机并发下发同名文件行为不变。
