# 上下文工程（Context Engineering）

> 目标：让 Agent 在有限上下文中优先获取与当前任务直接相关、可验证且版本受控的信息。

## 1. 知识来源

### 1.1 唯一知识来源

| 知识类型 | 存储位置 | 维护责任 | 更新时机 |
|---------|---------|---------|---------|
| 项目定位与能力 | `README.md`、`docs/features/` | 产品与开发者 | 产品能力变化时 |
| Agent 入口与约束 | `AGENTS.md`、`docs/harness/` | 变更开发者与 Reviewer | 架构、工具或流程变化时 |
| 需求与方案 | `docs/reqs/`、`docs/superpowers/` | 需求实现者 | 需求澄清、方案调整时 |
| API 契约 | `pkg/protocol/**/*.proto` | 接口维护者 | 接口变更时 |
| 生成 API 文档 | `docs/swagger/` | 接口维护者 | 协议重新生成时 |
| 数据模型 | `pkg/dal/table/`、`cmd/data-service/db-migration/` | 后端开发者 | 表结构变化时 |
| 构建与生成 | `Makefile`、`cmd/Makefile`、`scripts/` | 开发者 | 工具链变化时 |
| CI 验证 | `.github/workflows/`、`.golangci.yml` | 开发者 | 验证门禁变化时 |
| 前端规范 | `docs/standards/frontend-vue3.md` | Harness 预设维护者 | 前端技术栈变化时 |
| 接口规范 | `docs/standards/api-grpc-gateway.md` | Harness 预设维护者 | 接口协议变化时 |
| 后端规范 | `docs/standards/backend-generic.md` | Harness 预设维护者 | 后端技术栈变化时 |

当文档与代码、生成配置或 CI 不一致时，以可执行配置和当前源码为事实，并在同一任务中修正文档或明确记录偏差。

### 1.2 非权威来源

- 未纳入版本控制的即时通讯、口头约定和本地临时文件。
- 未注明版本、环境和采集时间的外部 Wiki、日志截图或监控截图。
- 已生成文件中与源 `.proto`、生成脚本冲突的手工改动。
- 与当前工作区不一致的旧分支、旧提交或历史对话结论。

## 2. 渐进式上下文披露

### 2.1 三层结构

```text
第一层：AGENTS.md
  └─ 项目概览、目录、关键规范和硬性协作约束
第二层：docs/harness/README.md、docs/standards/README.md、docs/dev-map/README.md
  └─ 按任务类型导航到对应规范与知识图谱
第三层：组件规范、需求/设计文档、协议、源码和测试
  └─ 只读取当前任务直接涉及的部分
```

### 2.2 任务加载顺序

1. 读取 `AGENTS.md`，确认仓库级约束和工作流。
2. 查询 `docs/dev-map/graph.json` 定位模块、入口和关联概念；图谱过期或无证据时搜索源码。
3. 读取受影响目录的实现、相邻测试、协议和生成入口。
4. 按变更端加载 `docs/standards/` 对应规范；任何代码变更均加载安全与评审规范。
5. 仅在任务需要时读取需求单、外部系统数据或生产观测数据。

### 2.3 上下文预算

- 单次优先读取索引和相关段落，超过 300 行的文件先搜索符号或关键词。
- 不重复加载已确认且未变化的内容；结论必须保留来源路径。
- 工作区存在未提交改动时，先区分用户改动与当前任务改动，禁止覆盖无关内容。
- 需求、代码和验证证据冲突时停止推断，回到源文件或请求用户决策。

## 3. 动态上下文

### 3.1 实时数据源

| 数据源 | 接入方式 | 用途 | 约束 |
|-------|---------|------|------|
| Git 工作区与历史 | Git 只读命令 | 识别变更范围、历史意图和用户已有改动 | 不执行破坏性回退 |
| TAPD | TAPD MCP，`project.json.workspace_id` | 拉取、澄清、评审和更新需求 | 写操作按 Skill 流程确认 |
| BSCP KV 配置 | `bk-bscp-prod-kv-config` MCP + `bkbscp-kv-config` | 查询或按授权变更 KV 配置 | 发布及写操作必须遵循闭环验证 |
| BSCP 文件配置 | `bk-bscp-prod-file-config` MCP + `bkbscp-file-config` | 查询配置元数据和下载内容 | 默认只读 |
| BSCP 进程配置 | `bk-bscp-prod-process-config` MCP + `bkbscp-process-config` | 按表达式启停托管、生成/检查/下发配置、同步 CMDB 与 GSE | 调用方默认已迁移；写操作必须先确认范围并轮询批次 |
| 代码结构图谱 | `graphify`、`docs/dev-map/graph.json` | 代码定位、依赖路径和概念查询 | 代码变化后增量更新 |

### 3.2 运行时与外部系统

代码集成包括 BK-IAM、BK-CMDB、GSE、ITSM、BKRepo、对象存储、MySQL、Redis、etcd 和 Kubernetes。Agent 不因代码中存在客户端而默认拥有环境访问权；必须使用任务明确提供且已授权的工具。

## 4. 更新机制

以下变化必须同步检查 Harness：顶层目录或服务变化、依赖方向变化、API/数据模型变化、构建与 CI 命令变化、Skill/MCP 变化、工作流变化。代码提交后运行文档园艺轻量检查；完整扫描发现的偏差进入同一 PR 或 TAPD/Issue 跟踪。

## 检查清单

- [ ] 结论引用了当前仓库或已授权动态数据源
- [ ] 只加载了与任务直接相关的组件文档和源码
- [ ] 已识别并保护用户未提交改动
- [ ] 接口、数据模型和生成文件均追溯到权威源
- [ ] 动态数据包含环境、时间和访问权限说明
- [ ] 结构或流程变化已同步更新文档与开发地图
